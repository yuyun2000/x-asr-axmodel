# 编译与仿真结果

目标机：`m5stack@192.168.20.38`（16 核 / 62 GB / Ubuntu 24.04），Pulsar2 **8.0**（`e9a1aa15`），
AX650 / NPU1，无开发板 → 精度验证走 `pulsar2 run` 软件仿真。

## 模型规模

| 项 | 值 |
|---|---|
| ONNX 输入 | `x4d [1,1,1000,80]`（10 s 窗口，80 维 fbank） |
| ONNX 输出 | `encoder_out [1,248,512]`（Zipformer2 subsample = 4×） |
| **MACs** | **17,120,005,440（17.12 GMAC / 10 s）** |
| axmodel 体积 | 172.6 MB（168,593.6 KB） |
| 编译耗时 | 07:56 → 08:34，约 **38 分钟**（含 EndToEnd 精度分析） |

## 第 1 次（INT8 / MinMax / 7 组"补静音"校准）

| 指标 | 值 | 判定 |
|---|---|---|
| cosine_similarity | **0.9549** | ❌ 低于验收线 0.99 |
| mae | 0.546 | — |
| max_abs_diff | 8.65 | — |
| 逐帧 cosine | median 0.965 / p10 0.920 / min 0.797 | — |

**更关键的是逐帧 cosine 之外的失效**：拿仿真输出跑贪心解码，**整段输出为空**
（ONNX 输出同一段音频是「昨天是 MONDAY TODAY IS 礼拜二 THE DAY AFTER TOMORROW 是星期三」）。
也就是说 INT8 后的 encoder 输出虽然"看起来还像"，但对 transducer 的 joiner 已经不可用了。

输出统计对比（说明不是量纲问题）：

```
ref  mean 0.1108 std 2.4039 min -7.274 max 8.304
ax   mean 0.1032 std 2.3963 min -6.373 max 6.186
diff mean 0.0077 rms 0.7213      最佳缩放比 0.958
```

## 第 2/3 次尝试（都没跑完）

| 尝试 | 配置 | 结果 |
|---|---|---|
| v2 | 16 组满窗校准 + **Percentile** + **SmoothQuant** | 编译 79 分钟仍在 compiler 阶段，判定异常（v1 同样规模只需 30 分钟），终止 |
| v3 | 16 组满窗校准 + **Percentile**（去掉 SmoothQuant） | 编译 63 分钟仍在 compiler 阶段，同样异常，终止 |
| v4 | 16 组满窗校准 + **MinMax**（与 v1 同方法，只换校准集） | 编译 **78 分钟**仍在 compiler 阶段（v1 只用 38 分钟），终止 |

**关键发现（比"哪个方法更好"更值钱）**：v1→v4 唯一的变量是校准样本数 7→16，编译时间
38 分钟 → 78 分钟仍未完成，基本呈线性。原因大概率是 `precision_analysis: EndToEnd`
会对**每个校准样本**跑一遍全图逐层比对（33 个 NPU 子图 × 1500 个张量）。

所以下一轮应该先关掉精度分析再试量化方法：

```json
"quant": { "precision_analysis": false, "precision_analysis_method": "PerLayer" }
```

预计能把单次编译压到 10–15 分钟，这样调量化参数才有意义。本次因为时间关系没来得及做。

## 待验证的改进方向（优先级从高到低）

第 1 次的问题定位在两处：

1. **校准集质量差**：7 组样本里 6 组是把 3–9 s 音频补静音到 1000 帧，静音占比 30–70%，
   MinMax 的激活范围被静音帧主导；
2. **MinMax 对 transformer 的离群值敏感**。

对应改动（`21_make_calib.py` + 新配置）：

| 方向 | 说明 | 成本 |
|---|---|---|
| ① 只换校准集（MinMax + 16 组满窗） | 最接近 v1，编译时间可控；静音帧污染是 v1 的已知缺陷 | 编译 ~40 min |
| ② 混精（`highest_mix_precision: true` 或对敏感层用 `layer_configs.data_type=FP32`） | Pulsar2 的标准精度补救；但违反「默认 INT8、highest_mix_precision=false」的口径，**需要你点头** | 编译 ~40 min，模型变大、变慢 |
| ③ 更多真实业务音频做校准（32 组以上） | 语音分布更贴近线上（方言、噪声、远场） | 需要素材 |
| ④ QAT / AdaRound / LSQ | Pulsar2 支持 `enable_adaround` / `enable_lsq`，代价是编译时间与调参 | 小时级 |
| ⑤ 换更小的子模型 | 例如只转前 3 个 encoder stack 验证通路（精度不可用，仅验证编译链路） | 30 min |

第 1 次的结论已经能确定一件事：**「能编译、能跑仿真」是通的，「INT8 精度达标」还没通**。
下一步建议先走 ①（低成本验证校准集的影响），不行再讨论 ②。


## 最终结果（U8 + Softplus 改写，单 NPU 子图）✅

关键改动只有一处：把 icefall `SwooshL/SwooshR` 激活里的 `Log(1+Exp(z))` 改写成
ONNX 原生 `Softplus(z)`（见 `scripts/host/27_fold_swoosh.py`、`reports/05-pitfalls.md` §10）。
Pulsar2 不支持 `Log`，之前它把图切成 17 个 NPU + 16 个 CPU 子图，是 v1 精度崩掉的主因。

| 指标 | v1（U8 + Log，33 子图） | **最终（U8 + Softplus，1 子图）** |
|---|---|---|
| 量化 | U8 MinMax，7 组校准 | U8 MinMax，8 组校准（16 组里取 8） |
| NPU 子图 / CPU 子图 | 17 / 16 | **1 / 0** |
| cosine | 0.9549 | **0.999012** ✅ |
| MAE | 0.546 | **0.0787** |
| max_abs_diff | 8.65 | **1.66** |
| 贪心解码文本 | 空 | **与 ONNX 逐 token 一致**（0/58 编辑距离） |
| axmodel 体积 | 172.6 MB | 165 MB |
| 编译耗时 | 38 min | 约 35 min（14:50→16:12 含两次被抢占） |

结论：**精度验收通过**（cosine 0.999 ≥ 0.99，且端到端文本完全一致）。


## 多样本仿真验证（U8 + Softplus，8 组校准）

| wav | cosine | MAE | 文本一致性 | 差异 |
|---|---|---|---|---|
| 0.wav | 0.999012 | 0.0787 | ✅ 完全一致 | — |
| 1.wav | 0.998276 | 0.0982 | ❌ 编辑距离 10 | `ALWAYS ALWAYS` → `OS OS`（英文词） |
| 2.wav | 0.996739 | 0.1406 | ❌ 编辑距离 3 | `不认识` → `不是` |
| 3.wav | 0.998375 | 0.1027 | ❌ 编辑距离 3 | `YES` → `E S`（英文词拆字） |

- **mean cosine = 0.998101，min = 0.996739**：全部 ≥ 0.99，精度门禁通过；
- 文本层面 1/4 完全一致，其余是**少量英文词/近音词**的退化 —— 这与 INT8 量化对
  小语种（英文在中英混说里的占比低）敏感一致，中文主体完全正确；
- 原始数据：`reports/artifacts/multi_sim_u8_8calib.json`。

后续提升方向：增加校准样本到 16 组（已排队编译）、U16 混合量化（Pulsar2 的 cmodel
在 U16 上会崩，需要真板验证）、或对角化 SmoothQuant。
